# Готовность к запуску (оценка 2026-10-29)

## Сервер

VPS: 2 vCPU, 1,95 ГБ RAM, своп 3,9 ГБ, диск 46 ГБ (занято 4,3 ГБ), Ubuntu 24.04. На одной машине Java (backend),
PostgreSQL и Caddy.

| | Сейчас |
|---|---|
| Занято RAM | ~720 МБ (Java ~590 МБ сразу после деплоя, PostgreSQL ~150 МБ, Caddy ~20 МБ) |
| Доступно | ~1,2 ГБ |
| Потолок Java | куча до 640 МБ (`-Xmx640m`) + метаданные, нити, модели лиц → под нагрузкой ~0,9–1 ГБ |
| База | 74 МБ |

Для теста и закрытой беты хватает. Для публичного запуска — 4 ГБ RAM (Java до ~1,5 ГБ кучи, больше кэша базе)
и вынести фото в объектное хранилище (S3-совместимое) с CDN.

## Архитектура

**Backend** — модульный монолит Spring Boot: пакеты по функциям (`accounts`, `auth`, `profiles`, `discovery`,
`social`, `chat`, `economy`, `boost`, `dates`, `safety`, `support`, `media`, `push`, `admin`, `testing` …), внутри
`api` / `application` / `domain` / `persistence`. Схема — миграции Liquibase (39 шт.), контракт API —
`docs/api-contract.md`, 210 интеграционных тестов на настоящей PostgreSQL (Testcontainers), CI на каждый пуш.

Открыта к расширению хорошо: новая функция — новый пакет + миграция + эндпоинты; премиум-функции и лимиты —
в конфиге/админке; лента собирается из независимых фильтров (`Specification`), новый фильтр добавляется рядом.

Слабые места:
- **Один экземпляр.** Лимиты запросов, SSE-подписки, билеты событий, кэш MusicBrainz живут в памяти процесса.
  Второй сервер потребует Redis (лимиты, pub/sub событий).
- **Фото на локальном диске** — нет CDN, бэкап отдельно от базы.
- `DiscoveryService` и SQL-функция ранжирования растут — следить, чтобы лента не стала узким местом
  (нет пространственного индекса для расстояний, см. `shortcut:` в коде).
- Модели распознавания лиц в той же JVM — память и CPU на загрузке фото.

**Мобилка** — Flutter, папки по функциям, простой `ChangeNotifier`, свой API-клиент, 89 тестов и стенд
скриншотов. Расширяется без проблем; `api_client.dart` большой — со временем разбить по областям.

**Веб** — React + Vite; отстаёт от мобилки (профиль, настройки, комментарии к увлечениям); кабинет персонала
внутри пользовательского веба (вынести — в TODO).

## Готовность к запуску

Функции продукта для MVP — в основном готовы: анкета и онбординг, лента с фильтрами и совместимостью, лайки,
мэтчи, чат (ответы, «печатает», план встречи), проверка селфи, жалобы и модерация, поддержка и FAQ, премиум,
бусты, обновление APK.

Что **блокирует** публичный запуск:

1. **Вход.** SMS-шлюз не подключён, на сервере включён режим фиксированного кода (`APP_AUTH_MOCK_ENABLED`):
   войти можно в чужой номер. Подключить SMS (или звонок/Telegram Gateway) и выключить мок.
2. **Тестовый режим на боевом сервере.** Testing API, сид-анкеты, авто-ответы ботов. Нужен отдельный тестовый
   сервер (или хотя бы выключить на боевом).
3. **Бэкапов нет** — ни базы, ни фото. Ежедневный `pg_dump` + копия медиа на другой сервер/хранилище.
4. **Оплата** — заглушка «Купить» выдаёт премиум бесплатно; настоящий провайдер не подключён.
5. **Пуши** не подключены (FCM) — без них мэтчи и сообщения теряются.
6. **Юридическое:** пользовательское соглашение, политика конфиденциальности, согласие на обработку ПДн
   (152-ФЗ), уведомление Роскомнадзора как оператора ПДн, хранение ПДн россиян в РФ, 18+, оферта для платежей,
   маркировка рекламы мест (ERID, 38-ФЗ).
7. **Карты:** договор с 2ГИС (плитки и поиск); сейчас — без ключа, только для тестов.
8. **Мониторинг:** нет алертов и сбора ошибок (Sentry или аналог), логи только на сервере.
9. **Безопасность** — отдельный аудит (запланирован).
10. **Магазины:** RuStore / Google Play — карточка, подпись боевым ключом, политика данных.

Итог: закрытая бета — можно сейчас (после выключения мок-входа для чужих номеров). Публичный запуск —
ориентировочно 2–4 недели работы (п. 1–5, 8, 9) плюс юридические документы и ИП/ООО.

## Платёжный провайдер (CloudPayments и аналоги)

Технически — да, это API после регистрации: виджет/SDK для оплаты, уведомления (webhook) о платеже с проверкой
подписи HMAC, рекуррентные платежи для подписки, облачные чеки 54-ФЗ (CloudKassir). У CloudPayments есть SDK
для Android и оплата через СБП. В бэкенде под это уже описан модуль `payments` (`docs/integrations.md`).

Но до API нужно:
- **ИП или ООО** (самозанятых CloudPayments официально не подключает — уточнить у них), расчётный счёт.
- **Заявка и проверка сайта** провайдером. На сайте: описание услуги и цены, оферта, правила возврата,
  политика конфиденциальности, контакты и реквизиты, HTTPS.
- **Онлайн-касса по 54-ФЗ**: облачная касса провайдера (регистрация кассы в ФНС и договор с ОФД — обычно
  оформляет провайдер, несколько дней).
- **Комиссия** — индивидуально, зависит от оборота и MCC; знакомства могут считаться повышенным риском.
- **Магазины приложений:** в Google Play требование платить только через их биллинг для пользователей из России
  не действует с 2022 года (их биллинг в РФ приостановлен) — для россиян можно своей платёжкой. RuStore —
  свой Pay SDK, правила о сторонних оплатах проверить перед публикацией. APK напрямую — любая платёжка.

Срок: бумаги и проверка — 1–2 недели; разработка (платёж, webhook, чеки, выдача премиума, продление
подписки, возвраты) — 3–5 дней.
